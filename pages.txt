We need to completely refactor the existing email automation system and migrate it to a clean, scalable architecture using Agenda + MongoDB + Brevo.

Current situation:
- Brevo email sending logic exists in controllers and/or cron-related files.
- Some email workflows may be triggered directly from API endpoints.
- There may be server-level cron jobs or manual scheduling logic.
- We want to replace all scheduled email automation with Agenda.

Goal:

Controller
→ Agenda Job
→ Worker
→ Brevo Service

No controller should send emails directly.

No scheduled workflow should bypass Agenda.

---

## TASK 1 — Audit Existing Implementation

Before making changes, scan the entire codebase and identify:

- All Brevo-related files
- All email sending functions
- Any cron jobs
- Any scheduled tasks
- Any direct calls to Brevo APIs
- Any controller methods currently responsible for sending emails
- Any duplicate scheduling implementations

Provide a list of findings before refactoring.

---

## TASK 2 — Create Dedicated Brevo Service

Create:

services/brevoService.js

Move ALL Brevo-specific logic into this file.

Create:

sendProjectFormEmail(emails, formUrl)

Requirements:

- Accept an array of recipient emails
- Accept a project form URL
- Build email content
- Send email through Brevo
- Use official Brevo SDK or Axios
- Throw meaningful errors
- No business logic
- No database queries
- No scheduling logic

This service should only be responsible for email delivery.

## TASK 4 — Create Email Worker

Create:

workers/emailWorker.js

Define a job:

send-project-form-links

Job flow:

### Input

Read:

projectId
formUrl

from:

job.attrs.data

### Runtime Database Query

When the job executes:

- Query MongoDB
- Find all users/employees assigned to the specified project
- Retrieve only email fields

Example:

User.find({ projectId }).select("email")

### Validation

If no users exist:

- Log warning
- Exit successfully

### Delivery

If users exist:

sendProjectFormEmail(emailList, formUrl)

## TASK 5 — Automation API

Create or refactor:

controllers/automationController.js

### Schedule Automation

Route:

POST /api/automation/schedule

Request:

{
  "projectId": "...",
  "formUrl": "...",
  "scheduleDate": "..."
}

Behavior:

agenda.schedule(
  scheduleDate,
  "send-project-form-links",
  {
    projectId,
    formUrl
  }
)

Return:

{
  "success": true,
  "jobId": "<agenda-job-id>"
}

Store the Agenda job ID so it can later be canceled.

---

### Stop Automation

Route:

POST /api/automation/stop

Request:

{
  "automationJobId": "..."
}

Behavior:

agenda.cancel({
  _id: automationJobId
})

Return:

{
  "success": true
}

This should immediately remove the pending Agenda job from MongoDB.

## TASK 9 — Security Audit & Hardening

While performing the migration, review the application for security issues and improve where appropriate.

### MongoDB Security

Verify:

- Credentials stored in environment variables
- Authentication enabled
- No unnecessary public exposure
- Sensitive collections protected
- Agenda jobs store minimal data only

### RBAC Security

Verify:

- Only Admin users can schedule automations
- Only Admin users can cancel automations
- Coordinators cannot create automations unless explicitly allowed
- Facilitators cannot create automations unless explicitly allowed

Identify:

- Missing authorization checks
- Privilege escalation risks
- Route protection issues

### API Key Security

Verify:

- Brevo API keys are never hardcoded
- API keys exist only in environment variables
- Secrets are never exposed to frontend code
- Email configuration is secure

### File Upload Security

Review:

- File type validation
- File size limits
- Upload authorization
- Storage strategy
- Potential malicious upload risks

Provide recommendations where necessary.

### Agenda Security

Ensure Agenda jobs never store:

- Passwords
- OTPs
- Access tokens
- Refresh tokens
- API keys
- Sensitive personal information

Store only:

{
  projectId,
  formUrl,
  automationId
}

or equivalent minimal metadata.
